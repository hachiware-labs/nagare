# Nagare 画面フロー概要

このメモは、既存のビジュアル画面資産を新しい Fable-5 UI に置き換える前に、
現在の画面フロー判断を残すためのものである。

## プロダクト方向

Nagare は、AI実行環境、エージェント、スキル、MCP接続、ドメイン、品質記録を使って
作業を進めるための制御画面である。

UIで最初に優先するのは見た目の磨き込みではない。空のアプリから最初の有用な作業へ
進む道筋を明確にし、その後も作業の実行とレビューを繰り返し追跡できることである。

## 基本原則

- 最初の作業を作るために必要なことだけを聞く。対象はプロジェクトと実行環境。
- 既定エージェントの配線をセットアップ負担として見せすぎない。
- 一覧と詳細は、両方を同時に見せる必要がある場合を除き、同じ画面に混ぜない。
- 作業一覧はスキャンしやすくし、詳細は独立した画面として開く。
- 2カラムの判断画面は避ける。左側のタブまたは工程選択と、1つの集中した作業面を優先する。
- ツール、スキル、MCP の利用可否は、次の操作が変わる場所でだけ見せる。
- スキルと MCP はグローバルなライブラリだが、割り当ては選択したエージェントに限定する。
- MCP追加は、接続テストに成功してからエージェントへ割り当て可能にする。
- プロジェクト整理役は設定可能にする。未設定の場合は Nagare の内蔵整理役を使い、
  その代替状態が分かるようにする。

## メインフロー

1. 空の作業状態
   - ユーザーはプロジェクト / 実行環境がまだ存在しないことを理解する。
   - 主操作からセットアップを開く。

2. プロジェクトセットアップ
   - ユーザーはプロジェクト名を入力し、作業フォルダを選択する。
   - ルーブリック / 評価条件の編集は任意にし、最初の作業を妨げない。

3. 実行環境セットアップ
   - ユーザーは検出済み実行環境を選択する。
   - 未検出の実行環境は通常の選択肢にしない。

4. AI 接続確認
   - Nagare は、少なくとも1つの利用可能なAI実行環境が接続されているか確認する。
   - 認証が必要、または接続に失敗した場合は、作業作成前にユーザーが修正する。

5. 作業ホーム
   - ユーザーは作業を状態別に見る。対応が必要、処理中、質問あり、完了など。
   - セットアップと接続確認が通った後、新しい作業を作れる。

6. 作業依頼入力
   - 依頼本文を主入力にする。
   - プロジェクトとモードは副次的な入力にする。
   - 自動構造化は記録するが、依頼入力の邪魔にしない。

7. 作業開始確認
   - ユーザーは依頼要約、AI構成、権限、レビュー条件を確認する。
   - 主操作で作業を開始する。

8. 作業実行中
   - ユーザーは選択中の工程、担当エージェント、現在の結論、次に期待される操作を追う。
   - 質問が必要な場合は人間の回答待ち状態へ進む。
   - 失敗した場合は失敗時の引き継ぎへ進む。

9. 成果物レビュー
   - ユーザーは生成された成果物、確認条件、根拠、判断を確認する。
   - 主操作で成果物を採用する。
   - 副操作で追加情報を求める、または差し戻す。

10. 作業完了サマリー
    - 作業一覧には完了バッジと回答サマリーを表示する。
    - 詳細は詳細操作から開く。

11. 作業詳細
    - ユーザーは最終結論、採用済み成果物、レビュー結果、エージェント履歴を確認する。

## 回復と改善

- 人間への質問: 現在の作業だけを止める。回答後は実行中またはレビューへ戻る。
- 失敗時の引き継ぎ: 原因、影響、回復案、引き継ぎ文脈、ログ要約を見せる。
  設定変更が必要な場合は作業開始確認から再開できるようにする。
- 品質記録: 繰り返し出るレビュー結果を記録し、ドメイン、エージェント、ルーブリックの改善提案に使える。
- 品質変更プレビュー: 改善案は適用前にレビューできるようにする。

## 管理領域

- プロジェクト: プロジェクト一覧と整理役の代替設定。
- ドメイン: ドメイン一覧、ドメイン基本情報、成果物別の知識またはルーブリック編集。
- 実行環境: 接続済み実行環境とモデル設定の一覧。
- エージェント: エージェント一覧、役割、実行環境、プロンプト、ドメイン範囲、割り当ての編集。
- スキル: インストール済みスキルの管理、定義済み一覧、ClawHub検索、GitHub URL / 手動ソースからの追加。
- MCP: スキルとは独立して MCP接続を管理する。エージェントへ割り当てる前に追加と接続テストを行う。
- インスペクター: 根拠、AI構成、生ログは診断面であり、明示的に開かない限り標準フローには出さない。
