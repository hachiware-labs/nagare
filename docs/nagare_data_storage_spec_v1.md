# Nagare データ保存・プロジェクト選択仕様 v1

## 1. 目的

Nagare の設定、エージェント、知識、ワーク履歴を一つの制御プレーンへ保存し、
作業フォルダごとに独立した `.nagare` 状態が意図せず作られることを防ぐ。

プロジェクトの作業フォルダは、エージェントが読み書きする対象である。Nagare の
状態保存先ではない。この二つを混同しない。

## 2. 用語

| 用語 | 意味 |
| --- | --- |
| データルート | Nagare が所有する唯一の永続状態の保存先。 |
| 作業フォルダ | プロジェクトが対象とするリポジトリまたはフォルダ。成果物を生成・変更する先。 |
| プロジェクト | データルートに登録された、作業フォルダ・参加エージェント・確認ポリシーの組。 |
| アクティブプロジェクト | 現在のUIとCLIが既定で表示・操作するプロジェクト。 |
| テストデータルート | テスト実行だけが明示的に使う一時的なデータルート。 |

## 3. 正本と所有境界

### 3.1 唯一の正本

通常利用時、Nagare はOSユーザごとに一つのデータルートだけを使う。

- Windows: `%LOCALAPPDATA%\\HachiwareLabs\\Nagare`
- macOS: `~/Library/Application Support/Nagare`
- Linux: `${XDG_STATE_HOME:-~/.local/state}/nagare`

データルートの変更は、明示的な起動オプションまたは環境変数でのみ行う。現在の
作業ディレクトリや、最後に実行したCLIの場所から自動的に決めてはならない。

### 3.2 データの配置

```text
<data-root>/
  settings.toml                 # schema_version、active_project_id、UI非依存の既定値
  agents/                       # 汎用・追加エージェント
  domains/                      # プロジェクト横断の共通知識
  artifact-types/               # 成果物とルーブリック。ディレクトリ名は内部互換名
  skills/                       # スキルの登録情報と管理対象の実体
  mcp/                          # MCP接続定義。秘密値はOS資格情報ストア参照にする
  projects/<project-id>.toml    # 作業フォルダ、参加エージェント、整理役、確認ポリシー
  state/ledger.json             # ワーク、実行、レビュー、判断、履歴
  artifacts/<work-id>/          # Nagareが記録する成果物スナップショット・参照情報
  backups/                      # 移行前・更新前の世代バックアップ
```

`settings.toml`、設定ファイル、`ledger.json` がNagareの正本である。作業フォルダには
Nagareの状態を新規作成しない。作業フォルダ内の実ファイルは成果物そのものであり、
Nagare はパス、ハッシュ、実行根拠を記録する。

### 3.3 所有の分離

| データ | 所有範囲 |
| --- | --- |
| エージェント、実行環境、スキル、MCP、ドメイン、成果物 | データルート全体 |
| プロジェクト名、アイコン、作業フォルダ、参加エージェント、整理役、確認ポリシー | プロジェクト |
| ワーク、実行トレース、レビュー、承認・差し戻し、成果物参照 | プロジェクトに関連付けたデータルート内の履歴 |
| 認証情報 | OS資格情報ストア。設定ファイルや台帳に平文保存しない |

## 4. プロジェクト選択と起動規則

### 4.1 選択規則

プロジェクトはIDで選択する。表示名や作業フォルダ名を識別子として使わない。

優先順位は次の通りとする。

1. 明示した `--project <id>` または `NAGARE_PROJECT`
2. データルートの `settings.toml` に保存された `active_project_id`
3. 未選択。プロジェクト一覧を表示する

データルートは `--data-root <path>` または `NAGARE_DATA_ROOT` でのみ上書きできる。
従来の `--root` と `NAGARE_ROOT` は移行期間の互換入力とし、作業フォルダを指す。
新しい通常起動の保存先を決めるためには使わない。

### 4.2 UI規則

- 全画面のプロジェクト文脈には、プロジェクト名と作業フォルダを表示する。
- プロジェクト切替は左ナビの「プロジェクト」から明示的に行う。
- UIの `localStorage` は表示上の一時状態だけに使う。アクティブプロジェクトや
  データルートの正本にしてはならない。
- 存在しない保存先、破損した状態、未登録の作業フォルダを検出しても、初期化・
  保存先解除・別プロジェクトへの切替を自動実行してはならない。

## 5. 保存保証

- 設定・台帳の更新は同一ボリューム上の一時ファイルへ書き出し、fsync後に原子的に置換する。
- 更新前の直近世代を `backups/` に保持する。保持数と暗号化方針は別途運用設定で定める。
- 同じデータルートを複数プロセスが更新しないよう、単一ライターロックを取得する。
- 読み込み時は `schema_version` を検証する。移行不能な状態を黙って初期化しない。
- ワーク実行開始時に、使用した設定とデータルートのスキーマ版をトレースへ記録する。

## 6. テスト隔離

テストは通常データルートに触れてはならない。

- Rust単体・結合テスト: テストごとの一時ディレクトリを明示的に `ProjectLayout` へ渡す。
- CLI/E2E/デスクトップE2E: テストランナーが `NAGARE_DATA_ROOT` を一時ディレクトリへ設定する。
- 実ユーザーのデータルートを使うテストは、明示的な手動スモークテストだけに限る。
- テスト用のプロジェクトやワークを通常のプロジェクト一覧へ混在させない。

## 7. 既存データからの移行

既存の `<workspace>/.nagare/` は互換データとして検出できるが、起動時に自動統合しない。

1. 移行画面で候補ごとに、プロジェクト名、絶対パス、最終更新、エージェント数、
   ワーク数を表示する。
2. ユーザーが一つ以上の候補を選び、インポート先プロジェクトIDを確認する。
3. コピー後に設定・台帳・成果物参照の整合性を検証し、結果を表示する。
4. 元データは検証完了まで読み取り専用で残す。削除またはアーカイブは、明示確認を
   経た別操作とする。
5. 同一の作業フォルダまたは同一の旧プロジェクトIDを二重インポートしない。

移行後は、データルートだけを起動の正本として扱う。古い `.nagare` ディレクトリを
探索して自動的に開いたり、最新日時で勝手に選んだりしてはならない。

## 8. 受け入れ条件

1. 通常起動を別の作業フォルダから行っても、同じデータルートと
   `active_project_id` を開く。
2. `--data-root` / `NAGARE_DATA_ROOT` を指定した実行は、その場所だけを読み書きする。
3. テスト実行後に通常データルートの設定、台帳、プロジェクト一覧が変化しない。
4. 不正・存在しない保存先で初期化が自動実行されない。
5. 移行画面は候補と件数を明示し、複数の旧状態を暗黙にマージしない。

## 9. 実装順序

1. データルート解決を `NAGARE_DATA_ROOT` / `--data-root` へ分離し、テストを隔離する。
2. データルートにプロジェクトレジストリと `active_project_id` を導入する。
3. 現在の `.nagare` データを読み取り専用で検出する移行ウィザードを実装する。
4. UIの `localStorage` からプロジェクト選択の責務を外す。
5. 保存の原子更新、ロック、世代バックアップを実装する。

この順序では、既存データを消さずに正本を一つへ移せる。
